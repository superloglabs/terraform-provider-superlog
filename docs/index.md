# Superlog Provider

Manage Superlog alerts, dashboards, and synthetic checks. Create an API key in Superlog under Settings → API keys. The provider acts as the member who created the key, in that key's workspace.

## Example Usage

```terraform
terraform {
  required_providers {
    superlog = {
      source = "superloglabs/superlog"
    }
  }
}

# Set SUPERLOG_API_KEY to an API key from Settings → API keys.
provider "superlog" {
  # https://superlog.sh for the EU region, https://us.superlog.sh for the US region.
  endpoint = "https://superlog.sh"
}
```

## Exporting existing configuration

Superlog can write Terraform for objects you already have. Use **Copy as Terraform** on an alert, dashboard, or synthetic check, or export the whole workspace with the API:

```shell
curl -s -H "Authorization: Bearer $SUPERLOG_API_KEY" https://superlog.sh/api/v1/terraform | jq -r .hcl > superlog.tf
```

The export includes an `import` block for each object, so `terraform apply` adopts the existing objects instead of creating copies. Secret header values of synthetic checks become sensitive variables to set. Pass `alertIds`, `dashboardIds`, or `syntheticCheckIds` (comma-separated) to export only some objects.
